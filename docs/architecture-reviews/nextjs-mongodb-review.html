Problem: one edit rewrites a whole collection blob, so a rev lock and a client 3-way merge exist only to survive it.

Solution: normalize into 9 collections behind a repo module; each write touches one document.

  • Delete KvMerge, rev, unsynced queue
  • Interface shrinks to per-entity calls
  • Locality: write bugs live in repo
ADR: kv_store kept read-only as rollback until 2 weeks post-cutover.

Problem: in-memory listeners tie realtime to one process and each refresh re-reads a whole blob.

Solution: change streams on a single-node replica set; the in-process broadcast is the second adapter.

  • Two adapters justify the seam
  • Refresh one doc, not one blob
ADR: convert VM mongod to replica set rs0, or stay on in-process broadcast.
