Problem: the cache acts local-first but syncs whole-key blobs, and a session that boots offline can never write back.

Solution: a full Turso DB per device. The repo module reads and writes it locally, and sync moves rows.

  • Zero-latency reads and writes
  • Offline writes sync later
  • Delete KvMerge, rev, unsynced queue
  • Two adapters: native sync, fallback B
ADR-001 (gate G0): native Turso Sync if all 10 checks pass, else fallback B on the same schema and repo module.

Native: last push wins

sequenceDiagram
  participant A as Device A offline
  participant S as Sync server
  participant B as Device B
  A->>A: edit bug X at 09:00
  B->>S: edit bug X at 10:00, push
  A->>S: back online at 12:00, push
  Note over S: X = A's 09:00 value

With lww.ts

sequenceDiagram
  participant A as Device A offline
  participant S as Sync server
  participant B as Device B
  A->>A: edit X, hlc 09:00
  B->>S: upsert X, hlc 10:00
  A->>S: upsert X WHERE hlc newer
  Note over S: guard fails, X keeps B's 10:00 value

Problem: the built-in rule orders by push arrival, so a device that comes back late overwrites newer work.

Solution: every push is rewritten into an upsert keyed by id that applies only when its hybrid clock is newer.

  • Deep: one rule, every table
  • Order-independent convergence (T2.3)
  • Keyed by id, not rowid
  • No UNIQUE/FK to jam pushes
